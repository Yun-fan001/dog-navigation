版本：v1.0 ｜ 性质：研究型工程项目（含代码实现、仿真验证、真实数据验证三阶段）

# 1. 项目概述

## 1.1 背景与问题定义

抗险救灾场景中，GPS 拒止/漂移、建筑倒塌导致地形剧变，地面四足机器人（机械狗）面临三个工程痛点：

1. **迷路/跑偏**：残垣断壁环境下轮式/腿式里程计与激光 SLAM 快速累积漂移，且缺乏全局约束；
2. **视角低、遮挡重**：狗载相机离地 ~0.4–0.8 m，大量地表信息被瓦砾遮挡；
3. **算力受限**：机载平台（Jetson 级）无法运行稠密跨视角匹配大模型。

与此同时，救援体系在灾后 24–72 小时内通常能获取高分辨率无人机正射影像（15 cm 级）或卫星影像。本项目研究：**如何利用 2D 俯视影像（卫星图/航拍正射图）作为先验地图，为算力受限的四足机器人提供全局定位锚定与建图辅助**。

## 1.2 现有方法的局限（立项依据）

| 路线 | 代表工作 | 局限 |
|---|---|---|
| 像素/边缘特征跨视角精匹配 | SliceMatch、CCVPE、HC-Net、FG2 | 依赖完整规则的人工结构（立面、道路边界）；残垣断壁下特征失效；且要求检索阶段先给对图块 |
| 视觉基础模型跨视角检索 | MegaLoc、AnyLoc、DINOv2 系 | 只给地点级粗定位（数十米），无法支撑导航级精度 |
| 灾后场景专门研究 | —— | 2026 年的损毁评估综述明确指出：部分/完全倒塌建筑场景下的定位是"基本未被探索的方向" |

## 1.3 三个创新点

- **创新点 A（核心创新）**：面向灾后场景的**高维拓扑图 + 轻量语义分割**节点体系——不依赖易碎的"建筑"语义，改用灾后稳定性筛选出的节点（道路网顶点、地形特征、硬质场地等），每个节点携带"语义类别 + 局部 2.5D 高程签名 + 拓扑度数"复合描述子；狗走过 3–5 个节点后，用**属性子图匹配 + SE(2) 几何验证**将其局部轨迹与全局俯视地图精确对齐。
- **创新点 B（系统骨架）**：**平面严格对准、垂直方向弹性松弛**的定位架构——全局匹配只输出 (x, y, yaw) 三自由度软约束注入因子图，高度/横滚/俯仰完全交给激光惯导里程计（LIO）与腿式运动学；参考 dddmr_navigation 全栈（Go2 已官方集成其 Gazebo 仿真）。
- **创新点 C（增益模块）**：**主动探头 + 路径微调**——以"下一节点预期信息增益/绕行成本"为准则做 next-best-node 路径微调，配合机身姿态/云台改变视点（停车扫视、抬头、转身）主动确认节点语义签名。

## 1.4 项目目标（可验收）

| # | 目标 | 量化指标（仿真环境） |
|---|---|---|
| G1 | 全局定位 | 狗走过 ≤5 个节点后全局定位成功率 ≥80%（蒙特卡洛 100 次，随机初始位姿误差 ≤30 m / ±180°） |
| G2 | 定位精度 | 对齐后轨迹 ATE 相比纯 LIO 漂移降低 ≥70%；稳态平面误差 ≤2 m（0.3 m GSD 影像下） |
| G3 | 节点可用性 | 灾后场景中稳定节点重复检出率（repeatability）≥60%，节点密度 ≥1 个/50 m（建成区） |
| G4 | 机载实时性 | 语义分割 ≥10 Hz（Orin Nano 级），单次图匹配 <200 ms，全系统 CPU+GPU 占用留有 30% 余量 |
| G5 | 主动感知收益 | 开/关主动探头对比：节点确认时间缩短 ≥30%，误关联率下降 ≥50% |

# 2. 系统总体架构

## 2.1 分层架构

```
┌─────────────────────────────────────────────────────────────┐
│ 离线层（地面站/云端，灾前或救援初期运行）                        │
│  航拍/卫星正射图 → 语义分割 → 全局节点图 G_g(V,E) + 节点目录      │
│  DEM/DSM → 地形特征节点 → 合并入 G_g                            │
├─────────────────────────────────────────────────────────────┤
│ 机载层（狗，实时）                                              │
│  相机 → 轻量分割 ─┐                                            │
│  激光雷达 → LIO ──┼→ 局部节点图 G_l(t)（滑动窗口，3–8 个节点）    │
│  腿式里程计 ──────┘      │                                     │
│                          ▼                                    │
│              图匹配器：G_l ⊆? G_g → SE(2) 假设集 + 置信度        │
│                          │                                    │
│                          ▼                                    │
│       因子图融合（GTSAM）：LIO 6-DoF 因子 + 全局 3-DoF 软约束     │
│                          │                                    │
│                          ▼                                    │
│       行为层：next-best-node 选择 / 探头扫视 / 路径微调           │
└─────────────────────────────────────────────────────────────┘
```

## 2.2 坐标系与状态定义

- **全局系 G**：俯视影像的投影坐标系（UTM/ENU），原点取影像左上角锚点；只在其上估计 (x, y, yaw)。
- **机体/里程计系**：LIO 输出完整 6-DoF 状态 `X = (x, y, z, roll, pitch, yaw, v, b_g, b_a)`。
- **弹性松弛的实现**：全局匹配结果不作为硬约束，而是作为 `(x, y, yaw)` 上的**先验因子**，协方差由匹配置信度自适应生成（置信度低 → 协方差大 → 自动降权，匹配失效时系统平滑退化回纯 LIO）。z/roll/pitch 永远不被全局因子触碰。
- **关键软件决策**：放弃扩展卡尔曼滤波（EKF）主框架，采用**增量平滑因子图（GTSAM / iSAM2）**，因为多假设数据关联（max-mixtures）、延迟鲁棒核、因子开关在因子图里都是一等公民。

## 2.3 技术选型（含备案）

| 模块 | 首选 | 备案 1 | 备案 2 | 选择理由 |
|---|---|---|---|---|

# 3. 创新点 A：灾后稳定节点体系与图匹配全局对齐

这是项目的核心创新与核心风险所在，单独成章。

## 3.1 节点定义：灾后稳定性筛选

**核心原则：不依赖"建筑"这个灾后易碎语义类。** 灾前卫星图上的建筑，灾后可能变成俯视纹理都变掉的瓦砾堆。节点类别按灾后稳定性排序选取：

| 优先级 | 节点类型 | 俯视可观测性 | 狗视角可观测性 | 灾后稳定性 |
|---|---|---|---|---|
| ★★★ | 道路网拓扑顶点（交叉口、急弯、断头路端点） | 路网分割+骨架化 | 分割道路掩膜的分支检测 | 极高（路基难被完全掩埋） |
| ★★★ | 地形特征（山脊/鞍部/冲沟，来自 DEM） | DEM/DSM 直接提取 | 激光高程图签名匹配 | 极高 |
| ★★☆ | 水域/河岸线拐点 | 分割 | 激光反射率异常 + 分割 | 高 |
| ★★☆ | 大型硬质场地（操场、停车场角点） | 分割 | 局部平坦度签名 | 中高 |
| ★☆☆ | 幸存建筑角点（仅作辅助） | 损毁评估筛选后 | 立面激光特征 | 低（需损毁评估过滤） |

**节点复合描述子**（每个节点一个结构体）：

```cpp
struct SemanticNode {
  int    id;
  NodeClass cls;            // 上表类别枚举
  double conf;              // 提取置信度
  // —— 几何签名 ——
  Eigen::Vector2d pos_xy;   // 全局系（离线侧）或局部队列系（机载侧）
  double yaw_hint;          // 若节点带方向性（如道路走向直方图主方向）
  // —— 2.5D 高程签名 ——
  float  elev_hist[16];     // 以节点为中心 20 m 邻域高程直方图
  float  roughness;         // 邻域地形粗糙度
  // —— 拓扑签名 ——
  uint8_t degree;           // 图上的度（如交叉口=3/4）
  float  edge_angles[4];    // 出边相对方位（排序归一化，旋转不变）
};
```

判别力来源：**单个节点可以认错，但 3–5 个节点的相对几何 + 属性做子图匹配，歧义指数级下降**。这就是"走少数节点后精准对齐"在数学上成立的原因。

## 3.2 离线层：全局节点图 G_g 构建（地面站，代码任务 A1–A5）

| 任务 | 内容 | 技术手段 | 验收标准 |
|---|---|---|---|
| A1 | 影像预处理管线 | GDAL/rasterio：正射校正检查、重投影到 UTM、GSD 统一、切片（1024×1024，重叠 128 px） | 任意输入 GeoTIFF → 标准切片集，投影误差 <0.5 px |
| A2 | 灾后语义分割 | SegFormer-B2 在 **RescueNet**（灾后 UAV 分割数据集）+ **xBD**（灾前/灾后建筑损毁对）上微调；类别：道路、水域、硬质场地、瓦砾堆、幸存建筑、植被 | 道路/水域 IoU ≥75%（RescueNet 测试集） |

**备案（不确定性处理）：**
- 若灾后正射图拿不到 → 用灾前卫星图 + xBD 训练的**损毁评估模型**过滤掉"幸存建筑"类以外的易碎节点，只保留路网/地形节点（这正是创新点 A 的叙事之一）；
- 若分割模型在瓦砾上崩 → 离线层退到 **SAM2 + 点提示交互式提取**（半自动，救援场景可接受），机载层不受影响；
- 若 DEM 分辨率太粗 → 用 UAV 影像做摄影测量 DSM（OpenDroneMap），或纯依赖路网节点 + 瓦砾堆高程签名。

## 3.3 机载层：局部节点图 G_l 构建（实时，代码任务 A6–A9）

| 任务 | 内容 | 技术手段 | 验收标准 |
|---|---|---|---|
| A6 | 机载轻量分割 | SegFormer-B0 → TensorRT FP16，仅保留 4 类（道路/水域/硬质场地/其他），输入 512×512，关键帧触发（位移 2 m 或转向 15°，非每帧） | Orin Nano 上 ≥10 Hz，道路 IoU ≥65% |
| A7 | 局部高程图 | grid_map：LIO 点云 → 5 cm 分辨率局部高程图（50×50 m 滑窗），提取高程直方图/粗糙度签名 | 与离线 DEM 同区域签名余弦相似度 ≥0.8（仿真验证） |
| A8 | 机载节点检测 | 三个检测器并行：①分割掩膜道路分支检测（骨架化后找度≠2 点）②高程图局部极值/鞍部检测 ③语义突变点。候选点聚类（DBSCAN，eps=3 m）确认为节点 | 节点重复检出率 ≥60%（关键指标，见 3.6） |

## 3.4 图匹配与全局对齐（代码任务 A10–A12）

**算法主线：种子生长式子图匹配**

```
输入：G_l（n≈3–8 节点）, G_g（N 可达数千节点）
1. 候选生成：对 G_l 中每个节点，按 cls + 签名余弦相似度取 G_g 中 top-K 候选（K=20）
2. 种子选取：取属性最独特的一对局部节点（如唯一的四叉路口），在 G_g 中枚举候选对，
   用边长（比例一致）与边夹角过滤 → 种子对应集
3. 生长扩展：从种子出发，按 BFS 逐节点扩展对应关系，每步做
   成对一致性检查：|d_ij^local − d_ij^global| < τ_d 且 |Δθ_ij| < τ_θ
4. 几何验证：对每组一致对应集（≥3 对），RANSAC 估计 SE(2) 变换 T，
   内点数 ≥3 且 RMSE < 2 m 才接受
5. 置信度：score = w1·内点率 + w2·属性相似度均值 − w3·RMSE，映射为因子协方差
```

| 任务 | 内容 | 验收标准 |
|---|---|---|
| A10 | 匹配器实现 | 单线程 <200 ms（N=5000，n=5）；仿真已知真值下 top-1 正确率 ≥90%（无损毁场景） |
| A11 | 多假设处理 | 置信度不足时保留 top-M 假设（M≤5），以 GTSAM **MaxMixture** 因子注入，由后续观测自然消歧 | 误关联率 ≤5% |
| A12 | 对齐输出 | 输出 (x, y, yaw) + 3×3 协方差 → 因子图先验因子；附"对齐事件"日志供分析 | 接口冻结，见 §6 接口表 |

**备案：**
- n<3 时不匹配，只累积窗口（创新点 B 保证此时系统靠 LIO 继续跑）；
- 若种子生长误匹配率高 → 换 **VF2 精确子图同构**（n≤8 时复杂度可接受）求全部候选解再加权；
- 若属性区分度不足 → 节点描述子换 **DINOv2 patch 特征**（384 维，预提取离线侧，机载侧只跑轻量 backbone 提对应区域特征），用特征相似度替代语义类别。

## 3.5 对齐后的持续锚定

对齐成功不是一次性事件：此后每检测到一个新节点并匹配成功，就注入一个新的全局先验因子，形成**持续漂移抑制**。因子图里 LIO 因子提供高频平滑轨迹，全局因子低频纠偏——频率解耦，互不干扰。

## 3.6 本项目第一关键路径实验（Gate Review 1）

**节点重复检出率（repeatability）是整个方案的单点风险**：灾后场景里狗两次经过同一位置，检出同一节点的比例若 <60%，图匹配窗口将长期凑不齐 3 个可靠节点。安排为第一个实证实验（见 §7.2），**不达标则触发备案**：节点定义从"语义节点"降级为"地形签名节点 + TERCOM 式高程剖面匹配"（狗走过的连续高程剖面与 DEM 条带做相关匹配，类似地形辅助导航），牺牲部分精度换稳定性。

# 4. 创新点 B：平面严格对准 + 垂直弹性松弛的定位骨架

## 4.1 状态估计架构

```
FAST-LIO2 (6-DoF, 10–20 Hz) ──→ BetweenFactor(6-DoF) ──→ GTSAM iSAM2
腿式运动学前向约束 (接触辅助) ──→ 辅助因子（LIO 退化时接管）
图匹配输出 (x,y,yaw)+Σ ────────→ PriorFactor(3-DoF投影) ┘
                                              │
                                        鲁棒核：Huber / DCS
                                        多假设：MaxMixture
```

**代码任务：**

| 任务 | 内容 | 技术手段 | 验收标准 |
|---|---|---|---|
| B1 | LIO 部署 | FAST-LIO2 适配 Go2 搭载的 Livox Mid-360（或 Velodyne），标定 LiDAR-IMU 外参（lidar_align + 标定板） | 仿真 5 min 闭环漂移 ≤0.5% 航程 |
| B2 | 腿式里程计 | 关节编码器 + 足端接触估计 → 不变 EKF（参考 VILENS 开源实现）；与 LIO 松耦合 | LIO 人为失效 30 s 内漂移 ≤3% 航程 |
| B3 | 因子图核心 | GTSAM：自定义 **Pose3→SE2 投影先验因子**（只约束 x,y,yaw，z/r/p 自由），实现 `evaluateError` 与雅可比 | 单元测试：因子残差/雅可比数值微分校验通过 |
| B4 | 自适应协方差 | 匹配置信度 score → 协方差映射函数（标定：仿真中扫描 score-RMSE 关系拟合）；失效时因子不注入 | NGPS 式平滑退化：匹配中断后系统回纯 LIO 无跳变 |
| B5 | 鲁棒化 | Huber 核 + DCS（动态协方差缩放）开关；MaxMixture 接口预留 | 注入 20% 外点因子时 ATE 退化 ≤10% |

## 4.2 为什么是"弹性"而不是开关

错误的全局对齐一次就能把轨迹带飞，所以：**永远不硬切换**。匹配结果以带协方差的软约束进入因子图，协方差大时影响力自然趋零；只有连续多次一致对齐后才收缩协方差。这条原则写入 B4 的实现与测试。

## 4.3 dddmr_navigation 复用清单

- 直接复用：Go2 Gazebo 模型与控制器接入、mcl_3dl（作对照基线）、perception_3d（地形可通行性）、局部/全局规划器；
- 需要替换：mcl_3dl 的全局定位角色由 §3 图匹配 + §4 因子图取代（mcl_3dl 保留为 baseline 对照，实验里要有它）；
- 需要新增：俯视影像 → 2.5D 期望观测的接口（A7 的高程图与影像语义层的配准）。

# 5. 创新点 C：主动探头 + 路径微调

## 5.1 行为原语（BehaviorTree.CPP 实现）

| 原语 | 触发条件 | 动作 | 代价 |
|---|---|---|---|
| `LookAhead` | 距预测节点 <10 m | 机身转向/抬头对准预测节点方位，提前捕获 | ~0 s（行进中完成） |
| `StopAndScan` | 当前位置匹配置信度低 | 原地 360° 扫视（机身自旋），多视角聚合分割结果 | ~6 s |
| `StandUp` | 遮挡严重时 | 后腿站立抬升视点 ~40 cm，扩大可视域 | ~3 s，耗稳定裕度 |
| `Detour` | next-best-node 判定收益为正 | 微调路径经过高价值节点（≤15 m 绕行） | 绕行时间 |

## 5.2 next-best-node 选择（代码任务 C1–C3）

评分函数（候选节点 i）：

```
score(i) = α · ΔI(i) / (1 + cost(i))
ΔI(i)   = 预期信息增益 = 当前未匹配节点数 × P(节点i可确认) × 节点i属性独特度
cost(i) = 绕行距离 / 平均速度 + 地形代价（perception_3d 可通行性图）
```

| 任务 | 内容 | 验收标准 |
|---|---|---|
| C1 | 视点/云台控制 | 首选**机身姿态控制**（零硬件成本，Go2 支持站立/俯仰机身）；备案：加装 2 轴舵机云台（~¥300） | LookAhead 下节点首检距离提升 ≥30% |
| C2 | 信息增益评估器 | 在线维护"未确认节点价值表"，输入 G_l/G_g 匹配状态 | 决策延迟 <50 ms |
| C3 | 行为树集成 | 与 dddmr 规划器对接：Detour 以临时 waypoint 注入全局规划 | 主动模式 vs 被动模式对照实验可一键切换（rosbag 可复现） |

**备案：** 若信息增益计算在机载算力下吃紧 → 降级为**脚本化扫视**（每到一个语义候选区固定执行 StopAndScan），仍保留大部分收益；LEAP 论文的对照实验表明脚本扫视也显著优于纯被动，只是不如学习式/增益式。

## 6.3 开发纪律

- dr_match、dr_fusion 的核心算法写为**无 ROS 依赖的纯库**，ROS 只在外层 wrapper——单元测试和 CI 不启动 roscore；
- 每个任务配 GoogleTest/pytest 用例，验收标准即测试断言；
- 所有实验用 rosbag + 配置文件可复现，`dr_eval` 一键出指标表；
- 分支策略：`main`（可复现基线）← `dev` ← feature 分支；每次合并跑仿真冒烟测试（10 min 场景，LIO 漂移与对齐成功率不劣化）。

### C. 开发纪律（防"硬写"红线）

1. **禁止让 AI 从零实现**：FAST-LIO2、GTSAM 求解器、mcl_3dl、分割 backbone、BehaviorTree 运行时——这些 fork 配置即可，硬写必然出隐蔽 bug；

4. 核心算法单测断言 = 计划书验收标准，不是"能编译即通过"。
